# Edge / Chrome 插件：安装、使用与验收

使用日常 Edge 或 Chrome 中已登录的 Instagram 标签页，在插件工作台导入账号表、开始采集并导出结果。**无需 PyCharm、Python、独立浏览器或调试端口。** 浏览器和插件工作页需要在采集期间保持运行。

扩展使用 Manifest V3 和标准 `chrome.*` API，最低 Chromium 版本为 120，适用于桌面版 Edge / Chrome。请使用仍在更新的浏览器。插件目录统一为 `extension`，Chrome 和 Edge 安装同一份目录即可。插件只能使用安装它的浏览器及同一用户配置中的登录状态；Edge 的登录不会自动共享给 Chrome。0.7.0 于 2026-10-20 在 macOS 的 Edge 155.0.4283.62、Chrome 155.0.8059.80 上通过隔离离线集成测试，真实登录采集仍需在 Chrome 中验证。完整变更及各版本验证范围见 [更新记录](../CHANGELOG.md)。

当前插件版本为 **0.8.1**，支持精致科技 / 经典简洁两种界面风格，颜色可独立选择深色 / 浅色 / 跟随系统，高级设置新增可交互的 i 说明。默认延续 0.7.0 的深色科技工作台，保留 0.6.0 的配置自动保存及 YouTube Key 本机记忆，支持月份、季度及自定义日期范围，并统一为 `extension` 目录。保留按所选平台下载账号模板。Instagram 正常打开账号主页，读取 DOM、页面内嵌 JSON，以及页面自己已经发起请求返回的帖子数据；只在日期或所需指标缺失时打开详情，不主动调用旧版固定私有采集接口。友好错误提示、诊断日志复制与下载继续保留。从旧目录升级时请先按下方迁移步骤处理；以后在同一目录更新时，先导出需要保留的结果，在 Edge 的 `edge://extensions` 或 Chrome 的 `chrome://extensions` 重新加载本插件，关闭旧工作台，再从扩展图标重新打开。

桌面工作台左侧是可滚动的配置区，底部开始 / 停止按钮保持可见；右侧按“准备账号 → 读取内容 → 导出报表”显示当前阶段。已读内容、已处理账号和待核对账号分开统计，运行进度与完整性提示不会混为一项。结果下载与诊断日志各有独立区域。小窗口切换为上下布局，支持 320 / 390 像素宽度；键盘 Tab 操作有清晰焦点。界面使用本地样式、系统字体和本地 SVG，不新增远程字体、CDN 或采集请求。

### 选择外观与阅读设置说明

工作台顶部的 **界面风格** 可在“精致科技”和“经典简洁”之间切换，**颜色模式** 可选择“深色”“浅色”“跟随系统”。两项互不限制，例如经典简洁也能使用深色。第一次打开或旧版配置缺少这些选项时，继续使用精致科技 + 深色。

选择立即生效并自动保存到本机。“跟随系统”会在操作系统切换明暗外观时同步变化；明确选择深色或浅色则保持选择。下次打开工作台或重启浏览器后会恢复。外观切换不重载页面，不改变账号表、采集参数、已有结果和任务进度，运行中也可操作。

0.8.1 的所有下拉框使用统一控件，收起与展开都跟随当前风格和明暗颜色，当前选项有勾选标记。点击标题可聚焦对应控件；按 Enter / 空格展开，用方向键或 Home / End 定位，Enter / 空格确认，Escape 取消，Tab 收起并继续移动焦点，也可输入选项开头文字定位。菜单会避开窗口边缘，底部空间不足时向上展开，不被左侧配置区裁剪。动态标签页、已保存选项与禁用状态会同步显示；选择值、配置保存和采集逻辑保持原有行为。

展开 **高级设置** 后，采集方式、批次 / 页数、帖子详情上限、页面操作间隔的标题旁各有一个 **i**。鼠标悬停或按 Tab 聚焦即可阅读；点击（键盘 Enter / 空格）会固定说明，方便移入说明区域阅读。再次点击、按 Escape 或点击外部即可关闭；滚动时说明会跟随可见的按钮，按钮移出可见区域或收起对应设置时关闭。说明浮层在窄窗口会自动调整位置，运行中不禁用说明按钮。

这些说明帮助判断参数如何影响速度与覆盖范围：快速检查不等于查全，批次不是帖子条数，详情上限只控制必要的补充访问，操作间隔会抵扣已花费的页面加载时间。它们不会替用户修改参数或发起请求。

旧版曾在已登录状态下遇到 `web_profile_info` 首次请求 HTTP 429。0.3.0 改用浏览器正常页面提供的数据，不会换接口重试该请求。**真实单帖自动读取已验证；0.4.1 阶段用户试用反馈无明显大问题，并于 2026-10-20 确认发布。** 此反馈不代表完整账号表、所有日期和指标均已逐项核对，详细在线验证边界仍保留如下。

2026-10-19 验证记录：在日常 Edge 的登录会话中，用生产页面读取器和采集器自动打开 `team_foxer` 主页和首条帖子（主页批次 1、详情上限 1）。返回帖子 `DegMojjjUqh`，点赞 **88**、粉丝 **3,244**、伦敦发布时间 **2026-10-15 06:22:37**，正文与链接读取成功。评论字段返回 0、播放字段不可用；本次没有独立人工确认评论总数。结果包含该帖的 `OK` 行及 `PAGE_INCOMPLETE` 提示，后者符合只读一条的限制。此前直接读取主页也确认了帖子总数 1,572 和首批 12 个链接。该验证未覆盖全部帖子、全表账号或在线导出核对。

0.4.0 离线验证：252 项扩展单元测试通过；隔离 Edge 集成测试通过，覆盖页面读取、被动响应复用、读取上限、停止/取消、Excel/JSON 导出、日志与恢复。模拟页面自行返回完整帖子字段时，同一帖由“主页＋详情”两次页面打开降为只打开主页一次，点赞等字段一致；插件额外发起的 Instagram API 请求为 0。该场景有 1 次模拟网站自身的数据请求，不能说整个网站没有请求。测试不连接真实账号，不代表线上耗时比例；0.4.0 的完整账号表速度仍待用户实测。

### 0.4.0 的速度优化

- 工作台不再逐行展示帖子，只显示进度、结果数量、友好提示和日志，完成或停止后直接点击「下载 Excel 结果」。原来的结果表只在账号结束时更新，本身不是主要耗时来源。
- 每读一批主页就处理这一批，先利用已经加载的日期与指标；已知不在目标日期内的帖子不再为了补指标打开详情。同一个帖子最多尝试一次详情，不反复打开隐藏指标。首条详情读取后还会检查一次主页缓存；如果主页自己的数据刚刚到达，就直接补齐剩余帖子，避免继续逐条打开。
- 默认「按日期快速检查」：当前批日期已确认、排除可识别的置顶后按时间向旧排列，且末尾至少 3 条都早于最早目标日期，就停止向历史扫描。这是节省访问的启发式，**仍标记完整性待核对，不会据此宣称无发布**。当前批的乱序帖子仍会检查；要检查更早或更多内容，选择「继续检查更多内容」。
- 滚动后没有新链接或有效日期时停止空滚；正常页面已就绪但帖子日期缺失时，只额外等约 2 秒，不再等满 25 秒。真正未加载出的页面仍保留加载超时。
- 默认页面操作间隔由 8–12 秒改为 3–5 秒，按两次操作开始时间计算，页面加载耗时会抵扣间隔。页面访问保持串行；遇到页面限制或捕获到 HTTP 429 就停止该平台，不自动重试。
- 进度分别显示 Instagram 页面操作、YouTube API 请求、当前账号、主页批次、发现条数、详情访问数和耗时。**Instagram 140 次操作可能包含主页打开、滚动和详情打开，不等于 140 次接口请求**；每次正常打开网页也可能带来网站自己的多次网络请求。

被动数据读取只在插件创建的专用标签中安装，复用网站自己的响应，不读取请求 Cookie、认证头或请求正文，也不复制登录凭据。安装晚于页面首批请求或站点结构变化时，仍回退到 DOM/内嵌 JSON/必要详情访问。不会为了追求速度猜测日期、把不可见指标填为 0，或把提前停止当成完整采集。

## 从旧目录升级

本次把原 `edge-extension` 改名为 **`extension`**。先停止任务并导出需要保留的结果和日志，再更新代码。在扩展管理页移除旧目录安装，从新 `extension` 目录重新加载；仅刷新旧扩展无法完成路径迁移。目录改变可能导致扩展 ID 和本地存储变化，旧结果不会自动迁移。重新打开工作台、导入账号表，YouTube Key 需要重新填写。此前版本的 Python 源码、启动脚本、旧模板生成器和不再使用的接口采集实现均已移除，用户本机已有输入和结果不被删除。

## 1. 第一次安装

1. 打开平常使用的桌面版 **Microsoft Edge 或 Google Chrome**，在同一个浏览器用户配置中访问 [Instagram](https://www.instagram.com/)，完成登录及页面要求的验证。
2. Edge 在地址栏输入 `edge://extensions`，Chrome 输入 `chrome://extensions`，然后回车。
3. 打开 **开发人员模式**。
4. 点击 **加载解压缩的扩展**（英文为 **Load unpacked**）。
5. 选择克隆或解压后的项目中的 `extension` 目录，目录内应直接包含 `manifest.json`：

   ```text
   social-metrics-new/extension
   ```

   Windows 和 macOS 均通过目录选择器选中该文件夹。macOS 也可按 `Command + Shift + G` 输入自己电脑上的完整路径。不要选择项目上层目录、ZIP 压缩包或单个 `index.html` 文件。加载后需保留扩展文件夹，移动或删除它会影响后续使用。

6. 加载后应出现 **Social Metrics · 社媒采集**。从浏览器工具栏的扩展菜单点击它，打开「社媒采集」工作台标签页；可将图标固定到工具栏，方便下次使用。

以上安装方式对应 [Microsoft Edge 官方本地加载说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading) 和 [Chrome 官方本地加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。当前通过本地加载安装，尚未发布到扩展商店。

插件使用当前浏览器配置中的正常登录页面，不会复制、读取或导出 Cookie 值，不会修改日常浏览器的登录配置。点击开始后，会在同一浏览器窗口中自动创建专用的主页标签，并在需要时创建帖子详情标签，正常访问账号主页、向下滚动并打开必要的帖子详情。原先选择的标签页不会被导航。登录状态由浏览器正常管理，插件只读取页面已提供的内容。

## 2. 先用一个账号试跑

先在 Instagram 页面打开 [@team_foxer](https://www.instagram.com/team_foxer/)，确认主页与帖子可见，保留这个标签页。

回到插件工作台，依次操作：

1. 点击左侧 **使用示例**。文件信息应显示 `@team_foxer`，共 1 个 Instagram 账号。
2. 平台选择 **Instagram**。
3. 在「连接 Instagram」中选择刚才的标签页。若列表没有更新，点击 **刷新标签页**。
4. 日期范围选择 **最近几天（含今天）**，天数填 **7**；时区选择 **英国 · Europe/London**。
5. 展开「高级设置」，保留 **主页最多读取 5 批**（含首次打开及后续滚动）、**每账号最多访问 40 个帖子详情**，采集方式 **按日期快速检查**、操作间隔 **3 至 5 秒**。主页批次可设为 1–50；详情访问上限可设为 1–500。不理解某项时，悬停、聚焦或点击标题旁的 **i** 查看说明。
6. 点击 **开始采集**，观察进度与运行记录。
7. 本轮结束或点击停止后，点击 **下载 Excel 结果**；需要结构化备份时再点击 **导出 JSON**。文件保存到当前浏览器的下载位置；如果浏览器启用了下载询问，选择自己的保存目录。

可以切换到其他标签页，但**不要关闭或刷新插件工作台，也不要手动导航或关闭插件创建的采集标签**。如果将采集标签跳转到其他页面，插件会停止继续使用它，避免覆盖你的操作。本轮结束会清理仍由任务控制的标签；登录验证页面及被你改跳的标签会保留。电脑睡眠、离线或浏览器停止页面运行可能中断任务。

首次通过标准：至少找到一条你在 Instagram 上确认属于目标日期的真实帖子，并核对账号、标题、链接、发布时间及可见指标。只看到「采集完成」或「无发布」，还不能判断功能已经通过验收。若示例账号最近 7 天确实没有发布，用你自己的单账号表，或改成一个已知有帖的日期，再验证一次。

## 3. 导入自己的账号表

第一次使用时，可以先下载模板：

1. 在「采集平台」选择 **Instagram**、**YouTube** 或 **Instagram 和 YouTube**。
2. 点击下方对应的 **下载 Instagram 模板**、**下载 YouTube 模板** 或 **下载混合模板**，保存 `.xlsx` 文件。下载模板不需要先登录 Instagram、填写密钥或开始采集。
3. 打开文件，参考「填写说明」中的链接格式，在第一张 **账号清单** 中填写，每行一个账号。**只有主页链接必填**，账号名和平台选填；平台实际按链接识别。
4. 示例只放在说明页，填写区默认不含真实账号。将示例中的 `your_username` 或 `your_handle` 换成自己的目标账号，不要填写帖子或 Reels 地址；可以继续向下添加账号。
5. 保存后，回到插件点击 **选择账号表格** 导入，选择「账号清单」并核对账号数量。直接导入未填写的模板时会提示补充主页链接。

下载模板不会更换已导入的账号或清空采集结果。Facebook 仍不支持采集，因此没有 Facebook 模板；旧表中的 Facebook 行仍会提示跳过。YouTube API Key 只填在工作台中，不放进模板。

点击 **选择账号表格**，支持 `.xlsx`、`.csv`、`.tsv`。文件在本机解析；每个文件不超过 **10 MB**，本轮所选平台合计最多 **500 个账号**。超出时请拆分表格。旧 `.xls` 文件请先另存为 `.xlsx`。

推荐使用下面三个表头，列顺序可调整：

```csv
账号名,主页链接,平台
Robin Foxer,https://www.instagram.com/team_foxer/,Instagram
```

Excel 有多个工作表时，在出现的「工作表」下拉框中选择真正的账号清单。先检查已识别的账号数量和页面提示，再开始采集。Facebook 及其他不支持的平台会提示跳过；主页链接缺失或无法识别的行也会列出提示。

Instagram 使用账号主页链接。YouTube 支持 `@handle`、`/channel/频道ID`、`/user/用户名` 和视频链接；旧 `/c/名称` 链接请先手动换成对应的 `@handle` 或 `/channel/频道ID`。

### 日期范围与时区

日期范围包括最近几天、指定一天、按月份、按季度、自定义范围。下方预览会显示实际起止日期和天数，开始前请核对：

- **按月份**：选择年月，自动从当月 1 日到最后一天；闰年 2 月包含 29 日。
- **按季度**：同时选择年份。第一季度 1 月 1 日至 3 月 31 日；第二季度 4 月 1 日至 6 月 30 日；第三季度 7 月 1 日至 9 月 30 日；第四季度 10 月 1 日至 12 月 31 日。
- **自定义范围**：开始和结束日期都包含在内，支持跨年，最多 366 天。空日期、无效日期或结束早于开始时会显示修正提示，不能开始采集。
- **原有模式**：指定一天只采一天；最近 N 天包含所选时区的今天，最多 366 天。

月份和季度始终保留完整范围，不会自动截到今天。范围包含今天或未来日期时，界面提示该时段尚未结束，只能读取目前已发布内容。季度年份默认为所选时区的当前年份，月份和季度也默认当前值；手动选择后，切换时区不会覆盖这些选择。

日期归属按所选时区判断。例如选择 `Europe/London` 时，不要直接拿北京时间跨午夜附近的日期判断是否漏帖。期间的夏令时变化不会让选中的日期少一天或多一天。Excel / JSON 的运行信息记录日期模式、起止范围和天数；各结果行使用简洁范围文本。

**选择整个季度不会自动扩大读取上限。** 更长或更早的日期范围可能需要更多主页批次和详情访问；达到上限仍未查全时保留已读结果并标记待核对。

## 4. YouTube 或两个平台一起采集

1. 导入包含 YouTube 账号的表格。
2. 平台选择 **YouTube** 或 **Instagram 和 YouTube**。
3. 展开 **YouTube API 密钥**，填写你自己的 YouTube Data API Key。
4. 设置日期后开始采集。混合采集时，还需选择已登录的 Instagram 标签页。

插件不读取本机的 `config.json`。默认勾选 **在本机记住 API Key**，填写后自动保存，刷新、关闭工作台或重启浏览器后会自动填入。取消勾选会删除已保存的密钥，当前页面的输入仍可继续使用；点击 **清除已保存密钥** 会同时清空输入并取消记住。保存或清除失败时会有中文提示，看到成功提示后才表示操作完成。

界面风格、颜色模式、平台、日期模式及其选项、时区、主页批次、详情上限、采集方式和操作间隔也会自动保存。日期范围输入暂不合法时不会覆盖上一次有效选择；“最近几天”重新打开后仍按当天计算。已恢复结果保留其原始运行信息，下一次采集的表单使用最新保存的配置。账号文件和 Instagram 标签页需重新选择，不自动采集。

配置与 Key 保存在当前浏览器用户配置的 `chrome.storage.local` 中，不通过浏览器账号同步。Edge、Chrome、不同用户配置及不同扩展安装之间不共享；卸载扩展或清除扩展数据会删除配置。密钥不进入结果文件、会话结果恢复记录或诊断日志；不要放在账号表格中。

YouTube 的短视频分类仅根据时长标记为**疑似 Shorts**，需要你在页面确认，不能把这一提示当成官方类型判定。

## 5. 结果与中断如何处理

右侧三个统计的含义如下：

- **已读内容**：已确认属于目标日期的有效帖子条数，同一账号可以有多条。
- **已处理账号**：按账号去重，同一账号同时有帖子和待核对记录也只计一次。未采集或中断占位记录不增加完成数量。
- **待核对账号**：需要人工核对的去重账号数，可能与已处理账号重叠。已有帖子但日期范围未查全时仍需核对。

“导出报表”阶段表示已取得结果可以下载，不代表全部账号和日期已经查全。停止、恢复及待核对状态会保留提示，不应只凭 100% 进度判断成功。Excel/JSON 中的结果状态说明：

- **有发布**：读取到有效发布时间属于目标日期的帖子；同一账号多条帖子会分成多行。
- **无发布**：有可信依据确认完整页面列表，且没有目标日期内的帖子；空白页面、滚动停止或几条旧帖都不能作为无发布依据。
- **待核对**：`PAGE_INCOMPLETE` 表示日期覆盖完整性还需核对，Excel 标为“待核对”，已读到的有效帖子仍以 `OK` 行保留，不能理解为这些帖子都采集失败。页面访问、登录、网络或中断等实际失败在 Excel 标为“抓取失败”；两者都保留在“待人工核对”工作表，JSON 内部状态仍使用 `FAILED` 并通过问题代码区分。
- **未采集**：前面的同平台账号触发了停止条件，此账号尚未发送采集请求。导出中仍归入 `FAILED` 待人工核对，JSON 另有 `skipped: true`，并关联最初失败的诊断编号。

页面不再渲染帖子明细，导出文件包含全部已读取结果。账号数量不等于帖子行数；同一账号可能同时有成功作品和待核对项，验收时要检查具体原因。对历史帖子较多的账号，最近 7 天可能已找到帖子，但仍因没有完整列表证据而附带待核对项。置顶、乱序或仅看到链接都不会被用来假定查全；没有有效发布时间的链接不会作为成功帖子导出。隐藏或只以缩略数字展示的指标会保留“未公开或不可用”，不会填 0 或冒充精确数值。

**下载 Excel 结果** 会生成独立 `.xlsx` 文件，包含「采集结果」「待人工核对」「本次运行信息」三个工作表；**导出 JSON** 保存运行信息与结构化结果。插件不会回填或修改原始账号表。当前仅维护插件，不再提供 Python 或原表回填流程。

遇到限制或需要停止时：

- **Instagram 要求登录、验证或提示暂时限制访问**：停止该平台本轮采集，余下 Instagram 账号显示未采集，其他平台继续。登录问题先在保留的采集页面完成验证；限制访问时先暂停，**不要立即多次重跑**。正常浏览器页面也可能受到平台限制。
- **页面或详情上限不足**：已读取的目标日期帖子会保留，同时附带 `PAGE_INCOMPLETE` 待核对记录。缺日期的帖子详情会优先读取；已知在日期范围之外的帖子不会为了补指标而打开。提高上限会增加页面访问量与耗时，应先针对一个账号核对。
- **点击停止**：停止安排后续页面操作，当前读取结束后保留已完成账号及当前账号已确认的帖子，未完成部分附带停止记录。按钮显示「正在停止」时先等待。
- **工作台被关闭或刷新**：插件会尝试从本次浏览器会话中恢复最近一轮结果；未完成账号标为待核对，不会自动重新请求。先导出恢复的结果，再重新导入账号表，决定是否重跑。

采集结果的恢复记录只保存在 `chrome.storage.session` 中。关闭浏览器、更新或重新加载扩展等操作可能清除记录，临时保存也可能失败，所以每轮结束请主动导出。开始新一轮采集或点击「清空结果」前，也请先导出需要保留的数据。诊断日志使用独立的本机存储，保留规则见下一节。

## 6. 出错后复制诊断日志反馈

页面出现问题时，先看错误提示卡：它会说明**发生了什么、下一步怎么处理、问题编号**。例如登录失效时先完成网页登录；限制访问时暂停等待；日期未查全时针对单个账号核对页面或调整读取上限。未知程序异常也会显示普通中文提示，不需要你阅读原始 JavaScript 报错。

如果按提示操作后仍无法解决：

1. 保留当前工作台，不要立即刷新或重跑，以免错过现场。
2. 找到「运行记录」旁的诊断操作，点击 **复制诊断日志**。
3. 将日志粘贴到你准备反馈的对话中，并补充“点击了哪个按钮、预期什么、实际出现什么”。由你自行决定是否发送；插件**不会自动上传日志或向任何人发送消息**。
4. 若浏览器不允许自动复制，页面会展开并选中日志，按 `Command + C` / `Ctrl + C` 手动复制。也可以点击 **下载诊断日志**，将 `.txt` 文件保存到本机，再自行选择是否附上。

展开诊断详情可在发送前检查内容。日志记录运行编号、插件及浏览器版本、阶段、平台、行号、操作标签、状态、耗时和经过处理的技术堆栈。Instagram 的 `page.started`、`page.completed`、`page.failed` 事件区分主页打开、主页滚动与帖子详情，`waitMs` 是主动等待时间，`readMs` 是成功操作中扣除等待后的用时，`scan.completed` 记录主页批次、详情访问数与停止原因；页面操作次数不代表网站全部网络请求数量。YouTube 继续记录 API 请求阶段。它与 Excel / JSON 采集结果是两种文件：**诊断日志不包含账号名称、帖子正文、请求/响应正文、Cookie 或 API 密钥**，未知异常的自由文本会被省略，技术路径与凭据会自动脱敏。

诊断保存与清理规则：

- 常规诊断日志保存在本机扩展存储中，保留最近 **3 份**，每份最多 **500 条、200,000 字符**；达到上限时会舍弃较早记录，日志中会显示省略数量。
- 刷新或重新打开工作台时，会尝试恢复最近的可用诊断日志。日志保存失败时会提示只能在本页保留，此时先复制或下载，不要依赖刷新恢复。
- **清空结果**只清除采集结果，不清除诊断日志，便于结果清理后继续排查。
- **清空诊断日志**清除本机旧日志并开始新的记录，采集结果仍保留；采集中不能清空。若有多个工作页正在使用，先回到运行中的页面结束任务。
- 卸载扩展或清除其浏览器数据可能移除本机日志；需要保留时先下载。

如果插件连工作台都未能正常启动，独立启动诊断仍会尝试显示错误卡，禁用开始按钮，并提供复制、下载入口。此时日志较短，至少包含插件版本、发生时间和启动问题编号；重新加载后也会尝试带回这次启动失败记录。无需提交密码或 Cookie 来定位启动问题。

## 8. 常见问题与更新

**加载时说找不到清单文件**：选错目录。应选择直接含 `manifest.json` 的 `extension` 文件夹。

**直接打开 HTML 后不能开始**：请通过 Edge 或 Chrome 加载扩展，再从扩展图标打开工作台；普通网页或文件预览没有扩展权限。

**正常主页能看，但插件提示待核对**：先看问题编号。`PAGE_INCOMPLETE` 表示没有足够证据确认日期已查全，已有成功帖子可以导出；它不代表登录失败。若是页面限制或登录验证，保留日志并按页面提示处理。0.4.0 起的正常采集日志应有 `page.*` 事件；若新一轮仍显示 `web_profile_info`，先确认加载了正确目录的 0.8.1，并关闭旧工作台后重开。恢复的旧诊断日志仍可能包含旧接口记录。

**找不到 Instagram 标签页**：确认在安装插件的同一浏览器用户配置中使用 `https://www.instagram.com/`，完成登录和验证后打开主页，再点击「刷新标签页」。Edge 和 Chrome 的登录状态不互通。登录页或验证页不应作为采集标签页。

**提示另一个工作页正在采集**：回到原来的工作页查看进度或停止。插件不允许多个工作页同时发起任务。

**代码更新后界面没有变化**：若还使用 `edge-extension`，先按上面的迁移说明移除旧安装并加载新目录。以后在同一目录更新时，先结束任务并导出结果；到 Edge 的 `edge://extensions` 或 Chrome 的 `chrome://extensions` 点击本插件的重新加载按钮，确认版本为 `0.8.1`，关闭旧工作台，再从扩展图标重新打开。必要时刷新 Instagram 页面。不要在采集期间重新加载扩展。仅切换工作台顶部的风格或颜色无需重新加载，可以在采集中使用。

反馈问题时先提供操作步骤、问题编号与诊断日志即可；确需账号或结果样本时，再自行选择补充。不要发送密码、Cookie 或 YouTube API Key。
